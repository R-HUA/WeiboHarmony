## 续轮关闭的两项发现

### 缓存裁剪与游标边界（代码与离线回归已关闭）

- 增加版本化 feed_boundary 表，记录每个账户/信息流完整快照的预期条数和是否发生截断。
- 读取时同时验证边界版本、有效标记与实际未过期行数。超出 500 条的截断、过期、被其它信息流挤出、旧版本缺少边界记录，均返回 needsRefresh=true 和空 cursor。
- 旧缓存内容仍可离线阅读；底部显示“缓存不完整，重新获取”，不会把边界失效伪装成已到末页，也不会用较远游标跳过未保存的帖子。重新获取成功后从新首页开始连续分页。
- 旧数据库采用增加表的迁移方式；不丢弃现有帖子。退出账户也清除对应边界记录。
- 整次读取与写入使用同一串行队列，避免读取的帖子、cursor、边界来自两个不同快照；失效的阅读锚点不再进入位置恢复流程。
- 取舍：本次选择边界失效后重新获取，不尝试猜测被截断位置的服务端游标。长会话超过缓存容量后重启，需要重新加载才能继续在线分页。

### 后台刷新阅读位置与顺序（代码与离线回归已关闭）

- 已有内容时，后台首页只暂存，不改变当前 posts、cursor、锚点或持久缓存，也不重新通知瀑布流数据源。
- “信息流已更新 · 点击查看”作为滚动内容之外的覆盖按钮出现，不在列表前插入行。
- 点击提示或主动下拉刷新成功后，使用新首页替换当前信息流，清除旧锚点并回到顶部；后续分页只使用该首页的 cursor，不拼接不连续的旧缓存尾部。
- 接受更新会推进查询代次，旧分页的迟到响应无法追加到新流；退出账户后的待展示结果也不能被接受。
- 刷新失败保留当前内容；明确返回空首页时持久化空流，避免旧缓存再次复活。
